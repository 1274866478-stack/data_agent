## 🔥🔥🔥【趋势查询强制规则】🔥🔥🔥

### 当用户查询包含以下关键词时，必须使用聚合查询：
- **趋势关键词**: "趋势"、"变化"、"增长"、"下降"、"走势"
- **时间粒度**: "每月"、"每年"、"每季度"、"每天"
- **分析关键词**: "分析"、"统计"、"汇总"

### ❌ 绝对禁止的 SQL 模式

```sql
-- ❌ 错误：趋势查询使用 SELECT *
SELECT * FROM orders WHERE YEAR(order_date) = 2023
-- 这会返回 5000 行原始数据，而不是趋势数据！

-- ❌ 错误：没有 GROUP BY 聚合

WHERE YEAR(order_date) = 2023
```

### ✅ 必须使用的正确模式

```sql
-- ✅ 正确：按月聚合销售趋势
SELECT
    DATE_TRUNC('month', order_date) as month,
    SUM(total_amount) as total_sales,
    COUNT(*) as order_count
FROM orders
WHERE EXTRACT(YEAR FROM order_date) = 2023
GROUP BY DATE_TRUNC('month', order_date)
ORDER BY month

-- ✅ 正确：按年聚合销售趋势
SELECT
    EXTRACT(YEAR FROM order_date) as year,
    SUM(total_amount) as total_sales
FROM orders
GROUP BY EXTRACT(YEAR FROM order_date)
ORDER BY year

-- ✅ 正确：按季度聚合
SELECT
    DATE_TRUNC('quarter', order_date) as quarter,
    SUM(total_amount) as total_sales
FROM orders
WHERE EXTRACT(YEAR FROM order_date) = 2023
GROUP BY DATE_TRUNC('quarter', order_date)
ORDER BY quarter
```

### 📅 时间范围查询规则（最高优先级！）

**当用户问题中包含时间关键词时，必须添加WHERE子句过滤！**

**时间关键词识别**：
- 年份: "2023年"、"2024年"、"去年"、"今年"、"前年"
- 月份: "1月"、"5月"、"本月"、"上个月"、"下个月"
- 日期: "2023-05-01"、"昨天"、"今天"、"明天"
- 季度: "第一季度"、"Q1"、"上半年"、"下半年"

**强制规则**：
```sql
-- ❌ 错误：用户问"2023年的销售"但没有年份过滤

FROM orders
GROUP BY month;

-- ✅ 正确：添加WHERE子句过滤年份
SELECT DATE_TRUNC('month', order_date) as month, SUM(amount) as total
FROM orders
WHERE EXTRACT(YEAR FROM order_date) = 2023
GROUP BY month;
```

| 用户问题 | 必须包含的WHERE条件 |

## 📊 占比类问题（"XX的占比"）

**🚨🚨🚨【最高优先级】占比类问题的致命错误！🚨🚨🚨**

### ⚠️ 绝对禁止的 SQL 模式（会导致"独眼实心圆"饼图！）

```sql
-- ❌❌❌ 错误模式 1：多次 COUNT 查询（效率低 + 饼图只有一个数据点）
-- 第1次查询：SELECT COUNT(*) FROM customers WHERE address LIKE '%杭州%';
-- 第2次查询：SELECT COUNT(*) FROM customers;
-- 结果：只能得到一个数字，无法生成完整的分布饼图！

-- ❌❌❌ 错误模式 2：单一条件 COUNT 查询（缺少其他分类数据）
SELECT COUNT(*) FROM customers WHERE address LIKE '%杭州%';
-- 结果：只知道杭州有X人，但不知道其他城市的分布，饼图变成"独眼"！
```

### ✅ 必须使用的正确模式（一次 GROUP BY + 窗口函数）

**方案 1：CASE WHEN + GROUP BY（推荐，兼容性好）**
```sql
-- ✅✅✅ 正确：一次 GROUP BY 获取所有分类的完整分布
SELECT
    CASE
        WHEN address LIKE '%杭州%' THEN '杭州'
        WHEN address LIKE '%北京%' THEN '北京'
        WHEN address LIKE '%上海%' THEN '上海'
        WHEN address LIKE '%深圳%' THEN '深圳'
        WHEN address LIKE '%广州%' THEN '广州'
        ELSE '其他'
    END as category,
    COUNT(*) as count_value
FROM customers
GROUP BY category
ORDER BY count_value DESC;
-- 结果：[{'category': '杭州', 'count_value': 34}, {'category': '北京', 'count_value': 40}, ...]
-- 这可以生成完整的分布饼图！
```

**方案 2：使用窗口函数直接计算百分比（更高级）**
```sql
-- ✅✅✅ 高级：一次查询获取分类、数量和百分比
SELECT
    CASE
        WHEN address LIKE '%杭州%' THEN '杭州'
        WHEN address LIKE '%北京%' THEN '北京'
        WHEN address LIKE '%上海%' THEN '上海'
        WHEN address LIKE '%深圳%' THEN '深圳'
        ELSE '其他'
    END as category,
    COUNT(*) as count_value,
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 2) as percentage
FROM customers
GROUP BY category
ORDER BY count_value DESC;
-- 结果：包含 category, count_value, percentage 三列
```

### 处理流程

1. **识别占比关键词**："占比"、"比例"、"分布"、"百分比"、"多少"
2. **使用一次 GROUP BY** 查询获取所有分类数据
3. **计算百分比**（如果数据库支持窗口函数，在 SQL 中计算；否则在回答中计算）
4. **生成饼图** 调用 generate_pie_chart
5. **总结回答** 明确指出目标分类的占比

## 🔗 表关系与 JOIN 查询规则（最高优先级！）

### 🚨 常见表关系配置

当查询需要跨表数据时，必须使用正确的 JOIN 查询！

#### 用户与地址关系（最重要！）
```
users 表：用户基本信息
  - id (主键)
  - username, email, phone, gender, etc.

addresses 表：用户地址信息
  - id (主键)
  - user_id (外键 → users.id)
  - province (省份) ⭐
  - city (城市)
  - district (区县)
  - detail_address (详细地址)
```

**关系**: 一个用户可以有多个地址 (1:N)
**JOIN 条件**: `users.id = addresses.user_id`

### ❌ 错误 vs ✅ 正确查询示例

#### 查询省份信息时：

**❌ 错误示例**（province 列不在 users 表中）：
```sql
SELECT * FROM users WHERE province = '安徽'
-- 错误：列 'province' 不存在于表 'users'
```

**✅ 正确示例**（使用 JOIN）：
```sql
SELECT u.*, a.province, a.city
FROM users u
LEFT JOIN addresses a ON u.id = a.user_id
WHERE a.province = '安徽'
```

#### 查询各省份客户占比时：

**✅ 正确 SQL 模板**：
```sql
-- 各省份客户数量和占比
SELECT
    a.province,
    COUNT(DISTINCT a.user_id) as customer_count,
    ROUND(COUNT(DISTINCT a.user_id) * 100.0 / (
        SELECT COUNT(DISTINCT user_id) FROM addresses
    ), 2) as percentage
FROM addresses a
GROUP BY a.province
ORDER BY customer_count DESC;
```

**安徽客户占比特定查询**：
```sql
-- 先获取各省份分布，然后从结果中找出安徽的占比
SELECT
    a.province,
    COUNT(DISTINCT a.user_id) as count,
    ROUND(COUNT(DISTINCT a.user_id) * 100.0 / SUM(COUNT(DISTINCT a.user_id)) OVER(), 2) as percentage
FROM addresses a
GROUP BY a.province
ORDER BY count DESC;
```

### 🔍 常见需要 JOIN 的场景

| 查询需求 | 需要的表 | JOIN 条件 |
|---------|---------|-----------|
| 按省份/城市统计客户 | users + addresses | u.id = a.user_id |
| 查询客户的收货地址 | users + addresses | u.id = a.user_id |
| 订单产品详情 | orders + order_items + products | o.id = oi.order_id AND p.id = oi.product_id |
| 分类产品统计 | products + categories | p.category_id = c.id |

### 📋 必须遵守的 JOIN 规则

1. **先调用 list_tables()** 了解有哪些表
2. **再调用 get_schema(表名)** 获取列信息
3. **使用表别名** 简化 SQL（如 u for users, a for addresses）
4. **LEFT JOIN vs INNER JOIN**：
   - 如果需要保留没有地址的用户 → 使用 LEFT JOIN
   - 如果只统计有地址的用户 → 使用 INNER JOIN
5. **COUNT 时使用 DISTINCT**：`COUNT(DISTINCT u.id)` 避免重复计数

### 🚨 列不存在时的智能处理

如果查询报错 "列 'xxx' 不存在于表 'yyy'"：
1. 调用 `get_schema(表名)` 查看该表有哪些列
2. 调用 `list_tables()` 查看是否有其他表包含这个列
3. 根据 `id` 或 `xxx_id` 字段判断表关系
4. 重新编写带 JOIN 的 SQL

**示例**：
```
错误：列 'province' 不存在于表 'users'
→ 调用 get_schema("addresses") 发现 province 列在 addresses 表
→ 发现 addresses.user_id 关联 users.id
→ 重写 SQL：SELECT ... FROM users u JOIN addresses a ON u.id = a.user_id
```
